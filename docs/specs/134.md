# Mobile: the group screen shows each member's balance and who pays whom

Issue: #134 · Runs on: `mac` · Status: waiting for gate 1

## User story

As a member of a group, I want to see on the group's screen who owes whom and how much, so that I know who should pay whom without doing the sums.

## Acceptance criteria

1. Given a group where A (me) paid 100000 VND split equally with B
   When I open the group's screen
   Then a balances section lists every member with their balance in whole VND, with thousands separators, "₫" and a sign: "Bạn +50.000 ₫" and "<B's email> −50.000 ₫"

2. Given a group where B owes me
   When I open the group's screen
   Then the payments that settle the group show as lines: "<B's email> trả Bạn 50.000 ₫"; and when I owe, "Bạn trả <C's email> 20.000 ₫"

3. Given a group with no expenses, or where every balance is 0
   When I open the group's screen
   Then the balances section says the group is settled ("Đã cân bằng") and shows no payment lines; members still appear with 0 ₫

4. Given the group's screen with the balances showing
   When I add an expense and it saves
   Then the balances and payments update to include it, without leaving the screen

5. Given the balances can't be loaded (network error or API error other than 401)
   When I open the group's screen
   Then the expenses still show and I can still add one; the balances section shows an error with a "Thử lại" button that reloads only the balances, and never shows stale or partial figures as if they were current

6. [security] Given the balances call gets 401 `unauthorized`
   When the screen loads or reloads balances
   Then the session ends through `useSessionGuard`, like every other call; any other failure leaves the session alone

## Assumptions

- The section goes on the group screen above the expense list, because it is the screen that already has members and expenses (#97).
- "Bạn" names the signed-in user, the same as "Bạn đã trả" in #97; everyone else is shown by email, because there are no display names.
- Positive balance means the group owes that member, as the API defines it (#96).
- Members are listed in the API's order (by user id), and the app does not reorder them.
- Balances are loaded with the group's expenses, in parallel, and again after a saved expense; a failure of one does not hide the other.
- A balances failure doesn't hide the add button, because the saved expense still shows in the list (unlike a failed expenses reload, #107).
- A 404 for the group is handled as the screen already handles it, because #97 settles it.
- A `userId` in the balances answer that is not in the group's member list (the two calls are not atomic) is shown as its member row or payment line with the text "Thành viên khác" in place of an email, never dropped, because dropping a row would hide a debt.
- While balances are loading, the section shows a loading line and no figures, because figures from an earlier answer must not look current.
- Amounts use the same VND formatter as the expense rows, so there are no floats.
- Each part (section, per-member row, payment line, settled state, error, retry) has a `testID` for Maestro.
- The evidence is Jest tests plus a Maestro flow on the iOS Simulator and on the Android emulator (`Pixel_9_API_35`), with a screenshot of each in the PR; the owner has no Android phone, so the emulator stands in for one.

## Out of scope

- Any API change: `GET /groups/:id/balances` (#96) is used as it is.
- Debt per pair of members (A owes B for each dinner): only the settle payments and balances.
- Recording a payment ("I paid B") and settling up.
- A web screen for balances (the web has no group screen yet).
- Display names, push notifications, and sharing the balances as an image.

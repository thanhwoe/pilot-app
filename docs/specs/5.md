# Sign in with an email one-time code: API

Issue: #5 · Runs on: `cloud` · Status: waiting for gate 1

## User story

As a member of a group, I want to sign in with a one-time code sent to my email so that I can use Góp on the web and on my phone without a password.

## Acceptance criteria

### Requesting a code

1. Given a valid email address
   When I ask for a sign-in code
   Then the API answers 204, a 6-digit code is created for that email, and the code is printed to the API log instead of being emailed
2. Given an email with surrounding spaces or capital letters
   When I ask for a code and then sign in with it
   Then it is treated as the same email trimmed and lower-cased
3. Given a value that is not a valid email
   When I ask for a code
   Then the API answers 400 and no code is created

### Signing in

4. Given I asked for a code
   When I enter that code with the same email for the first time
   Then I am signed in, I get a session, and an account is created for that email
5. Given an account already exists for my email
   When I sign in with a new code
   Then I am signed in to that same account and no second account is created
6. Given I entered a code that does not match
   When I submit it
   Then the API answers 401 and I get no session

### Who am I

7. Given I am signed in
   When the app asks the API who I am
   Then it gets my account id and email
8. Given no session, or a session token the API does not know
   When the app asks the API who I am
   Then it gets 401

### Abuse cases

16. [security] Given a code older than 10 minutes
    When I submit it
    Then I am not signed in
17. [security] Given a code I already used to sign in
    When I submit it again
    Then I am not signed in
18. [security] Given I asked for a code and then asked for another
    When I submit the first code
    Then I am not signed in
19. [security] Given 5 wrong attempts against my current code
    When I then submit the correct code
    Then I am not signed in, and I must ask for a new code
20. [security] Given I asked for 5 codes for one email in the last 15 minutes
    When I ask for another
    Then the API answers 429 and no code is created
21. [security] Given any email, whether or not it has an account
    When I ask for a code
    Then the response is the same 204
22. [security] Given a wrong, expired, reused or never-requested code
    When I submit it
    Then the API answers 401 with the same body in every case
23. [security] Given a code that is not exactly 6 digits, or an email longer than 254 characters
    When I submit it
    Then the API answers 400
24. [security] Given a session older than 30 days
    When the app asks the API who I am
    Then it gets 401
25. [security] Given codes and sessions have been created
    When the database is inspected
    Then it holds no sign-in code or session token in plain text
26. [security] Given I signed in
    When the API log is read
    Then it contains no session token
27. [security] Given the dev code endpoint flag is not set
    When a client asks the dev endpoint for an email's code
    Then the API answers 404
28. Given the dev code endpoint flag is set and I asked for a code
    When a test asks the dev endpoint for my email's code
    Then it gets the current code, so UI tests can sign in
29. [security] Given the API runs in production and the dev code endpoint flag is set
    When a client asks the dev endpoint for an email's code
    Then the API answers 404
30. Given I am signed in
    When I sign out through the API
    Then that session's token gets 401

## Assumptions

- Sessions are an opaque bearer token returned by the API, which clients send in the `Authorization` header. One contract serves both clients; how the web and mobile keep the token belongs to #6 and #7.
- Codes are 6 digits and may start with 0, because a fixed-length numeric code is easy to type on a phone.
- A code lives 10 minutes and works once, and asking for a new code cancels the old one, because that is the usual one-time-code behaviour.
- 5 wrong attempts per code and 5 codes per email per 15 minutes, because limiting attempts alone lets an attacker keep asking for fresh codes.
- Wrong, expired and never-requested codes look the same, and asking for a code always answers 204, so the API never hints whether an account exists.
- Sessions last 30 days with no sliding renewal, which keeps mobile signed in across restarts without long-lived tokens.
- Signing out deletes the session on the server, so a copied token stops working.
- The only way a code leaves the API is the log, as the issue asks. This is a deliberate exception to `REVIEW.md`'s "no tokens in logs" for the code only; session tokens are never logged.
- The dev code endpoint exists only for automated UI tests, is off unless an env flag turns it on (decided on the issue, option a), and never answers in production.

## Out of scope

- Web and mobile screens (#6, #7).
- Sending real email. The code goes to the API log.
- Passwords, social login and magic links.
- Editing a profile or changing the email.
- Remembering the email between sign-ins, resending a code with a countdown, and listing or revoking other sessions.
- Rate limits by IP address. Limits apply per email only.
- Groups and anything else that needs a signed-in user. Later issues use the session check this issue adds.

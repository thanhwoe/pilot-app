# CI: run the Maestro flows on the macos-sim runner

Issue: #26 · Runs on: `mac` · Status: waiting for gate 1

## User story

As the repository owner, I want a pull request that touches the mobile app, its API or the shared package to run the Maestro flows on the Mac mini runner, so that its checks show the end-to-end result instead of only a session's report.

## Acceptance criteria

1. Given a PR that changes `apps/mobile/**`, `packages/shared/**` or `apps/api/**`
   When the PR is opened or pushed to
   Then a `mobile-e2e` job runs on the runner labelled `self-hosted, macOS, ARM64, macos-sim`, and it runs `pnpm --filter @gop/mobile e2e:ios` and then `pnpm --filter @gop/mobile e2e:android`, one after the other
2. Given a PR that changes none of those paths
   When the PR is opened or pushed to
   Then no `mobile-e2e` job runs
3. Given another end-to-end run (a session on the Mac mini) holds `scripts/e2e-lock.sh`
   When the job starts
   Then it waits on the lock instead of breaking either run, and the wait shows in the job log
4. Given a flow fails
   When the job ends
   Then the job fails and uploads Maestro's output and `apps/mobile/e2e/api.log` as an artifact
5. Given the job ends, passed or failed
   When the job's last step has run
   Then the simulator and the emulator it started are shut down, so the next session finds the machine free
6. [security] Given a PR from a fork
   When the PR is opened or pushed to
   Then `mobile-e2e` does not run on the self-hosted runner
7. [security] Given any run of the job
   When it executes
   Then it reads no repository secret and sets no token beyond the default read-only `GITHUB_TOKEN`
8. Given the job runs
   When it has run for 60 minutes
   Then it is stopped (a 60-minute timeout)

## Assumptions

1. The issue has no user story, scope or non-goals section. The story above comes from its first paragraph; scope is the CI workflow only, as the issue lists nothing else.
2. The job lives in a new workflow file, not in `ci.yml`, because a job-level `if` can't skip on paths and `paths:` filters apply to a whole workflow. Its check appears only on PRs that touch those paths. It is not a required check, since the repo has no branch protection.
3. A new push to the same PR cancels the earlier `mobile-e2e` run, as `ci.yml` does, and its cleanup (criterion 5) still runs.
4. "Waits on the lock" uses `scripts/e2e-lock.sh` as `e2e:ios` and `e2e:android` already do; the default wait of 1800 s applies. A lock that stays held longer fails the job (exit 75).
5. The job runs the two platforms in separate steps, so a failure of `e2e:ios` still lets `e2e:android` run, and both outputs are uploaded. The job fails if either failed.
6. The job sets `PATH` so Docker's CLI is found (the launchd note in the issue) and starts Postgres with `pnpm db:up` if it is not running. It does not stop Postgres afterwards.
7. The artifact is kept for 7 days, like the Playwright report.
8. Criteria 1 to 8 are about a workflow file, which no unit or API test in the repo can run. They are checked by workflow validation (`actionlint`) plus real runs on the runner, as described in the matrix.

## Test matrix

| AC | Test | Level | Where |
| --- | --- | --- | --- |
| 1 | Workflow lint passes; a PR touching `apps/mobile/**` shows `mobile-e2e` running `e2e:ios` then `e2e:android` on the `macos-sim` runner | manual (PR run) | `.github/workflows` |
| 2 | A PR touching only `docs/**` shows no `mobile-e2e` check | manual (PR run) | `.github/workflows` |
| 3 | Start `e2e:ios` in a session, push to the PR: the job log shows "e2e-lock: waiting for another end-to-end run" and neither run fails | manual (PR run) | Mac mini |
| 4 | Break one flow on a throwaway PR: the job is red and the artifact holds Maestro output and `api.log` | manual (PR run) | `.github/workflows` |
| 5 | After a passed run and a failed run, `xcrun simctl list devices booted` and `adb devices` list nothing | manual (Mac mini) | Mac mini |
| 6 | Workflow condition requires `github.event.pull_request.head.repo.full_name == github.repository`; checked by reading the lint output and by a fork PR, or the condition if no fork exists | manual (review) | `.github/workflows` |
| 7 | Workflow text has no `secrets.` reference and sets `permissions: contents: read`; a grep in review | manual (review) | `.github/workflows` |
| 8 | Workflow text sets `timeout-minutes: 60` | manual (review) | `.github/workflows` |
| A3 | A second push cancels the run and leaves no booted simulator or emulator | manual (Mac mini) | Mac mini |

Why manual: no test tool in the repo runs GitHub Actions workflows. The PR must carry as evidence the links to the green and red `mobile-e2e` runs and the log lines for criteria 3 and 5.

## Out of scope

- Changing the Maestro flows, `e2e/run.sh` or `scripts/e2e-lock.sh`.
- Making `mobile-e2e` a required check, or adding branch protection.
- Running on pushes to `main`, or on a schedule.
- Running the web Playwright tests on the Mac mini.
- Installing or updating the runner, Maestro, Xcode, the Android SDK or Docker on the Mac mini.
- Posting the result to the PR as a comment.

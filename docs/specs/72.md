# Web: one shared controlled field for the text fields of action forms

Issue: #72 · Runs on: `cloud` · Status: waiting for gate 1

## User story

As the developer, I want one shared component for the text fields of forms that use `useActionState`, so that the next action form keeps text typed while the action is pending from the start, instead of a flaky test or a bug report finding it after the fact.

## Acceptance criteria

1. Given the three action-form text fields in `apps/web` (the create-group name, the sign-in email and the sign-in code)
   When the code is read
   Then all three render the one shared component, and none of them keeps its own `useState` and `onChange` copy of the pattern

2. Given any of the three fields and a held Server Action
   When text is typed while the action is pending and the action then fails
   Then the field still holds the typed text, and the existing `#51 AC 1`, `#55 AC 1` and `#59 AC 1` tests pass unchanged

3. Given the create-group form
   When a create succeeds
   Then the field is cleared only if it still holds the name that was created, and the existing `#20 AC 3`, `#54 AC 3, 4` and the other create-group tests pass unchanged

4. Given the sign-in form
   When the member comes back from the code step with "Dùng email khác"
   Then the email field starts from the email the step gives it, a new code step starts with an empty code field, and the existing `AC 5` and `#59` tests pass unchanged

5. Given I create a group and then create another one with the same name
   When each create succeeds and I typed nothing else while it was pending
   Then the name field is empty after each of the two creates

## Assumptions

- The shared piece is a component, `ActionTextField`, in `apps/web/src/app/action-text-field.tsx`, because the owner decided so on the issue. It renders only the `<input>`; each form keeps its own `<label>`.
- It takes an optional starting value read once, and every other input property (`id`, `name`, `type`, `inputMode`, `autoComplete`, `maxLength`, `required`) passes through, so copy and attributes stay as today.
- The sign-in form still remounts the email and code fields when the step changes, so the email starts from the step's email and the code starts empty.
- The create-group form passes the action's result, not only the name: the field clears when a new result arrives and still holds the name it carries (#54). This also covers two creates with the same name, which the API allows.
- No existing test changes. One new e2e test is added for criterion 5; it passes before the change and must still pass after, so it need not fail first.
- Playwright runs in CI if the cloud environment can't reach its browser.

## Out of scope

- Any change to what a form does or shows, and any change to copy.
- Any change to the API, `packages/shared` or mobile.
- A new rule: `CLAUDE.md` already has the "Action forms" rule.
- A shared hook, which the owner decided against.

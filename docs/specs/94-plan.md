# Plan: Groups: invite by link and join, on the API and the web

Issue: #94 · Spec: [94.md](94.md) · Runs on: `cloud` · Status: waiting for gate 2

## Contracts

- **Migration** `apps/api/drizzle/0003_*.sql`, generated by `db:generate`: one nullable column on `groups`, `invite_token_hash text`, with a unique constraint. Existing groups keep `NULL` (no link). Additive. One link per group, so one column; replacing the link overwrites it.
- **Token.** `randomBytes(32)` as base64url, hashed with `hashSecret(token, AUTH_SECRET)` as sessions are, as the owner's comment says. That is 43 characters of `A-Za-z0-9_-`. A new shared `inviteTokenSchema` holds that shape, so the API, the web and later the mobile app agree on it.
- **Shared schemas** (`packages/shared/src/groups.ts`):
  - `createInviteResponseSchema` `{ token }`.
  - `inviteTokenBodySchema` `{ token: string }`, the body of the two calls below.
  - `invitePreviewResponseSchema` `{ groupName: string, alreadyMember: boolean }`.
  - The join answers with the existing `groupResponseSchema`.
- **Endpoints.** The token travels in a request body, not in the URL, because the API logs every request URL and a link that can be used must not end up in a log.

  | Method and path           | Request     | Success                                 | Errors                                                     |
  | ------------------------- | ----------- | --------------------------------------- | ---------------------------------------------------------- |
  | `POST /groups/:id/invite` | none        | `201` `{ token }`                       | `401 unauthorized`, `404 not_found`                        |
  | `POST /invites/preview`   | `{ token }` | `200` `{ groupName, alreadyMember }`    | `400 invalid_request`, `401 unauthorized`, `404 not_found` |
  | `POST /invites/join`      | `{ token }` | `200` the group (`groupResponseSchema`) | `400 invalid_request`, `401 unauthorized`, `404 not_found` |
  - **Make or reset a link.** Any member may. The first call makes the link, each later call replaces it and ends the old one. A non-member, an unknown group and a malformed id all get the same `404 not_found`, and no link.
  - **Preview and join.** Order of checks: session (401), then that the body has a string `token` (400), then the token. A token that does not match the shape, matches no group, or was replaced gets the same `404 not_found` with the same body, on both calls. Joining when already a member changes nothing and answers `200` with the group.
  - **Clients.** `GroupsApi` gains `createInvite`, `previewInvite` and `joinWithInvite`, and `flow.ts` gains the three matching functions that read a 401 through `guardSession`, as `loadGroups` and `submitGroup` do.
- **Web routes.** `/invite/<token>` (a page) and the sign-in page's `next` query parameter. `next` may only be `/invite/<a 43-character token>`; anything else becomes `/`.

## What the code does today

Read in full: `apps/api/src/groups/{routes,store,memory-store,store.contract,store.test}.ts`, `auth/secrets.ts`, `db/schema.ts`, `packages/shared/src/groups.ts` and `groups/{api,flow,copy}.ts`, `session-guard.ts`, `api-client.ts`, and in `apps/web`: `src/proxy.ts`, `src/app/{page,groups,actions,create-group-form,account}.tsx`, `sign-in/{page,actions,sign-in-form}.tsx`, `session/clear/route.ts`, `lib/{api,rejected-session}.ts`, `e2e/helpers.ts`, `playwright.config.ts`, and the first 70 lines of `actions.test.ts` and `groups.test.ts`.

- **Joining is the missing write.** `group_members` holds `(group_id, user_id, joined_at)` with a primary key on the first two. The only way in today is `createGroup` (the creator) and the tests' `addMember` helpers. `GroupStore.findGroupForMember` is the one membership check every group route uses.
- **Hashing already exists.** `hashSecret(value, authSecret)` is an HMAC keyed by `AUTH_SECRET`; `generateSessionToken()` is `randomBytes(32).toString("base64url")`. Sessions store only `tokenHash`. A link is the same shape, so lookups are by the hash (a unique index). Changing `AUTH_SECRET` signs everyone out today and will also end every invite link.
- **Request URLs are logged.** `server.ts` builds the app with `logger: true`, and Fastify's request logger writes the URL. That is the reason for the bodies above.
- **The web redirects with a proxy.** `src/proxy.ts` (matcher `/` and `/sign-in`) sends a signed-out GET of `/` to `/sign-in` and a signed-in GET of `/sign-in` to `/`, looking only at whether the cookie exists. Sign-in ends with `redirect("/")` in `sign-in/actions.ts`, and `sign-in/page.tsx` is a static page that renders `SignInForm`. Nothing carries a return address today.
- **`cacheComponents` is on.** Request data (`cookies`, `params`, `searchParams`) must be read behind a `<Suspense>` boundary, as `Home` does for `Account` and `Groups` (the Next guide "Authentication with Cache Components" says the same). The invite page and the sign-in page's `next` follow that.
- **Rejected sessions.** Server Components call `redirectRejectedSessionFromComponent()` and Server Actions call `endRejectedSessionInAction()`; `groups.test.ts` and `actions.test.ts` show how to test both with mocked `next/headers` and `next/navigation`.
- **Stale comments.** `grep -rniE "until invites exist|invites" apps packages --include=*.ts --include=*.tsx` finds three comments saying the test helper `addMember` stands in "until invites exist" (`groups/memory-store.ts`, `groups/store.contract.ts`, `expenses/routes.test.ts`). The helper stays, because tests need a chosen join time and `joinGroup` uses the clock. Step 1 corrects the comments.
- **Schema readers.** `grep -rn "from(groups)\|insert(groups)" apps/api/src` finds only `insert(groups)` in `groups/store.ts`, with named columns, and every select there names its columns, so a new column changes no result shape.
- **Open PRs.** `gh api repos/{owner}/{repo}/pulls` returns none.

## Risks

- **Question for the author. Answer this before adding `plan-ok`; the build reads the answer.** Is the wording in the table above right? In particular the note that says the link is shown once (AC 8 asks the page to say it) and the single message for any bad link.
- **The link is a secret in a URL.** It will sit in the browser history and in the address of `/sign-in?next=…` while someone signs in. The API never sees it in a URL (bodies), but the web server's own request line does. Nothing in the pages loads another site, so it is not sent as a referrer. I did not add a `Referrer-Policy` header, which would be a config change outside the spec.
- **Open redirect.** Criterion 4 needs the sign-in page to send people to a place named in the address, which is how open redirects happen. `safeReturnPath` allows exactly `/invite/<43-character token>`, and the action re-checks the hidden field instead of trusting the page. The spec has no `[security]` criterion for this, so I suggest adding one at the next revision. Step 4 tests it on its own.
- **Any member can end the link,** because there are no roles yet (the owner's answer). A member can make a new link at any time and leave the others' copies dead.
- **`AUTH_SECRET` rotation ends every link,** as it ends every session. Members make new ones.
- **Two members resetting at once.** The last write wins; the other member's link is dead and their page showed it once. They make another.
- **No limit on tries.** A token is 256 random bits, so guessing is not a realistic attack, and the three calls need a signed-in session. I did not add an attempt limit; the spec asks for none.
- **Clipboard on plain HTTP.** `navigator.clipboard` works on `localhost` and HTTPS only. On another HTTP address the copy button fails, and the link is still in a field the member can select. A signed-in visitor copying from a phone on the LAN is the case to try in a real browser.
- **The spec has no 401 criterion for the three calls.** Steps 3, 5 and 6 test them anyway, as `#31` did for groups.
- **Mobile.** The mobile deep link is a separate `mac` issue. It can reuse the shared calls, flows and copy added here.
- **Rollback.** Revert the commits. The migration only adds a nullable column; to undo it on a database, `ALTER TABLE groups DROP COLUMN invite_token_hash`. No deployed environment exists yet.

## What the code does today

Read in full: `.github/workflows/mobile-e2e.yml`, `scripts/e2e-lock.sh`, `apps/mobile/e2e/run.sh`, `.github/actionlint.yaml`, `.github/workflows/pr-evidence.yml` and `docs/specs/26-plan.md`.

- **Paths (AC 1, 2).** `on.pull_request.paths` has three entries: `apps/mobile/**`, `packages/shared/**`, `apps/api/**`. The workflow file itself is not one of them. All four files the spec adds exist at the repo root or under `.github`: `scripts/e2e-lock.sh`, `pnpm-lock.yaml`, `docker-compose.yml` and the workflow.
- **Cancel (AC 5).** Each run step starts `pnpm … e2e:ios` (or `e2e:android`) in the background under `set -m`. Its trap is `trap 'kill -TERM -- -"$pid"; wait "$pid"; exit 143' INT TERM`. A cancel runs the trap, which exits 143 before the `cp apps/mobile/e2e/api.log …` line, so `api-ios.log` and `api-android.log` are never copied. `mkdir -p "$RUNNER_TEMP/e2e-out"` also comes after the trap is set, though the "Note the start" step has already made that folder. The Android step has `if: ${{ !cancelled() }}`, so a cancel during iOS skips it and only `api-ios.log` is expected there. The upload step (`failure() || cancelled()`) and the collect step (`always()`) already run after a cancel.
- **Port 3101 (AC 3, 4).** `run.sh` starts the API on 3101 and refuses to start while anything listens there (`Port 3101 is already in use; stop that process first.`). Its `stop_api` runs on `EXIT`, so a run the runner kills hard can leave the API behind. The cleanup step already takes the e2e lock through `scripts/e2e-lock.sh` with `E2E_LOCK_WAIT=120` and runs a generated `cleanup.sh` under it. If the lock is not free in time, `e2e-lock.sh` exits 75, `cleanup.sh` never runs and the step prints a warning, so "if the lock stays held, stop nothing" already holds by construction. `cleanup.sh` starts with a check that exits 0 when the job stopped before "Note the start".
- **Who else uses 3101.** The web Playwright run starts its API on 3101 (`apps/web/e2e/servers.ts`, `playwright.config.ts`), and `test:e2e` runs through `scripts/e2e-lock.sh` (`apps/web/package.json`). So under the lock no other end-to-end run is using 3101.
- **Readers.** `grep -rn "api-ios.log\|api-android.log\|mobile-e2e-output" .` finds the names only in `mobile-e2e.yml` (lines 65, 79, 92) and in `docs/specs/49-plan.md` (a prose mention). Nothing is renamed or removed in this plan.
- **Tools.** No test tool in the repo evaluates a workflow, and CI does not run `actionlint`. `.github/actionlint.yaml` exists and declares the `macos-sim` label. `actionlint` is not installed in this cloud session. `lsof`, `nc` and `python3` (with PyYAML) are.
- **Open PRs.** `gh api repos/thanhwoe/pilot-app/pulls` returns none, so nothing else touches the workflow.

## Risks

- **A public repo, a self-hosted runner and wider triggers.** After this change a PR that edits the lockfile, `docker-compose.yml`, `scripts/e2e-lock.sh` or the workflow runs on the Mac mini. The fork guard is unchanged and still keeps outside PRs off it. A same-repo PR that changes `pnpm-lock.yaml` runs `pnpm install --frozen-lockfile` there, as a change under `apps/api` already does. The owner's plan to require approval for outside collaborators' workflows (the issue's note on security) is a repository setting, not part of this change.
- **The cancel grace period.** The runner sends a cancelled step `SIGINT`, then `SIGTERM`, then kills it after a short time. If `run.sh` takes longer than that to stop (an Xcode build, for instance), the shell is killed before the second `save_log`. The first `save_log`, before `kill`, keeps the log up to the cancel; only lines written while stopping are at risk. Step 6's two cancels show what survives on the real runner.
- **A web or session run on 3101 without the lock.** Cleanup stops whatever listens on 3101 while it holds the lock. `test:e2e`, `e2e:ios` and `e2e:android` all take the lock, so they are safe. A Playwright run started by hand without it, or a dev server someone put on 3101, would be stopped. `CLAUDE.md` puts the dev API on 3001.
- **Cleanup now runs even if the job stopped early.** It frees 3101 before the "stopped before it noted what was booted" check, so a job cancelled while it waits for the lock can still clear a listener an earlier killed run left. It still takes the lock first.
- **One runner, long jobs.** Step 6 queues behind any real run and can use several hours of Mac mini time. A throwaway job that is not cancelled uses up to the 60-minute timeout, and the 60 minutes also counts a long lock wait.
- **The lockfile edit.** A comment or blank line in `pnpm-lock.yaml` might be rejected by `--frozen-lockfile`. The job still ran, which is all AC 1 needs. If it matters, use a no-op change that `pnpm install` accepts.
- **Rollback.** Revert the commits: the workflow returns to the three old paths, the old trap and the old cleanup. No data, app code or other workflow is touched.

# Docs: add A4, A5 and A7 rows to the #26 test matrix

Issue: #49 · Runs on: `cloud` · Status: waiting for gate 1

## User story

As a reviewer of the `mobile-e2e` workflow, I want the spec's test matrix to list the lock timeout, the Android-after-iOS-failure behaviour and the artifact retention, so that each promised behaviour has a recorded check.

## Acceptance criteria

1. Given `docs/specs/26.md`
   When it is revised
   Then its test matrix has a row `A4`: a lock held past `E2E_LOCK_WAIT` fails the job with exit 75
2. Given `docs/specs/26.md`
   When it is revised
   Then its test matrix has a row `A5`: `e2e:android` still runs after `e2e:ios` fails
3. Given `docs/specs/26.md`
   When it is revised
   Then its test matrix has a row `A7`: the artifact is kept for 7 days
4. Given `docs/specs/51.md`
   When it is revised
   Then its AC 2 reads `pnpm --filter @gop/web test:e2e --repeat-each=10 e2e/groups.spec.ts`, with no `--` before the flags

## Assumptions

1. The three behaviours are Assumptions 4, 5 and 7 of the #26 spec, so the rows use the `A<k>` labels, placed after the existing `A3` row.
2. The rows are `manual`, like the rest of the #26 matrix, with the evidence the issue says exists (the run links on the #26 PR).
3. Criterion 4 comes from the issue's "Added from PR #56" section, which asks for it explicitly.
4. The "do not change the acceptance criteria" non-goal covers the #26 spec only. Changing #51 AC 2 is the one edit the issue asks for there.

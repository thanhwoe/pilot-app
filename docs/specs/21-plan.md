## Verification

- Steps 1–5 (cloud): `pnpm lint && pnpm typecheck && pnpm test`, and `pnpm turbo run build --filter=@gop/web` for the page change in step 1. The web Playwright suite (`pnpm --filter @gop/web test:e2e`) runs in CI, or on the Mac mini if the cloud environment blocks Chromium.
- Step 6 (mac): `pnpm db:up`, then the flows above. `verify` mobile on the Mac mini is step 6's by-hand check, with the iOS and Android screenshots (AC 2, 3). No `verify` for the API, because nothing there changes. The web needs none: its text doesn't change.
- Each test that guards a fix (A4, A5, A6) is shown to fail with only that fix removed, then the fix is restored. The PR carries the failing output.

## Risks

- **Production code changes in `index.tsx`.** The create flow shares the new `load` function and the same refs as the code #14, #19 and #23 test. Their tests (the four in `home.test.tsx` and the Maestro groups flows) must stay green after every step.
- **Question for gate 2: the create's reload.** When a create finishes with the list in an error state, it reloads the list, as now. The plan keeps that reload from showing the loading line, so the screen goes from the error straight to the list, as now. The spec asks for the loading line only on the first load and on the retry. If you want it on the create's reload too, say so and step 3 changes.
- **Screenshots depend on a relaunch with the API down.** A relaunch with the API stopped keeps the session and shows the error (the account line shows its own error too). If an app version signed the user out instead, the screenshot would be of sign-in; the build would stop and report it.
- **Mac mini load.** Step 6 must not overlap another simulator or build session: one at a time on `macos-sim`. The e2e lock handles two e2e runs but not a build session.
- **Rollback:** the change is two strings, a screen change and tests. Reverting the PR restores today's behaviour, and nothing in the API or the data depends on it.

# Test: #20 AC 3 web e2e test is flaky, main is red

Issue: #51 · Runs on: `cloud` · Status: waiting for gate 1

## User story

As the developer, I want the web end-to-end tests to pass or fail only because of the code under test, so that a red `CI` run means something and main stays green.

## Acceptance criteria

1. Given the cause of the intermittent failure of `#20 AC 3` is found
   When the fix is in
   Then the PR names the cause, and a test fails reliably without the fix in a way that shows that cause

2. Given the fix
   When `pnpm --filter @gop/web test:e2e --repeat-each=10 e2e/groups.spec.ts` runs
   Then every one of the 10 runs of `#20 AC 3: a valid name after a failed create creates the group and clears the field` passes

3. Given a signed-in user submits a group name of only spaces and then a valid name
   When the second submit completes
   Then the group is created and listed with its name and "1 thành viên", the name field is empty and no error is shown (if the cause is in the app, the fix goes in the app, not the test)

## Assumptions

- A "reproduction that fails reliably before the fix" is a test or harness step that forces the cause (for example a controlled delay or ordering), because the cause is unknown and the issue gives that as the example. If the cause is in the test only, this reproduction may be a temporary demonstration shown in the PR rather than a committed test.
- The fix must not use Playwright `retries`, longer timeouts or `test.fixme`, as the issue's non-goals say.
- Existing tests stay as they are, except `#20 AC 3` if the cause is in that test.

## Out of scope

- Playwright `retries`, longer timeouts or `test.fixme`.
- Changes to other tests.
- Changes to mobile, the API or `packages/shared`, unless the cause turns out to be there (then back to the author).

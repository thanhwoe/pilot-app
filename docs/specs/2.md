# Health check reports the API version

Issue: #2

## User story

As the developer, I want `GET /health` to report the API version so that I can tell which build is running.

## Acceptance criteria

1. Given the API is running
   When a client calls `GET /health`
   Then the response includes `version`, equal to the `version` in `apps/api/package.json`
2. Given a response without `version`
   When it is parsed with `healthResponseSchema`
   Then parsing fails
3. Given the web home page loads and the API is up
   When the status line renders
   Then it shows the API version next to the status

## Test matrix

| AC  | Test                                                                                              | Where                                  |
| --- | ------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 1   | `GET /health` returns `version` equal to `apps/api/package.json`, both when the DB is up and down | `apps/api/src/app.test.ts`             |
| 2   | `healthResponseSchema` rejects a body without `version`, and an empty `version`                   | `packages/shared/src/health.test.ts`   |
| 3   | Home page status line reads `API: ok · v<version> · DB: up`                                       | Manual check with screenshot in the PR |

The web app has no test runner yet, so AC 3 is checked by hand against the running stack.

## Out of scope

- No change to the mobile app. It parses with the same schema, which still accepts the new body.
- No git SHA or build time, only the package version.

# Web: check that one-time-code autofill still fills the controlled sign-in code field

Issue: #67 · Runs on: `mac` · Status: waiting for gate 1

## User story

As someone signing in on the web from a phone, I want the SMS or keyboard suggestion for my sign-in code to fill the code field and be accepted when I press "Đăng nhập", so that I can sign in without typing the code.

## Acceptance criteria

1. Given I am on the code step on a phone and my keyboard offers the code it found
   When I pick the suggestion and press "Đăng nhập"
   Then the code is in the field, it is submitted, and I am signed in

2. Given the same suggestion fills the field
   When the page re-renders (for example after a failed request)
   Then the field keeps the filled code

## Assumptions

- The deliverable is a check first and a fix second: if autofill fills the code field, submits it and keeps it across a re-render on the iOS Simulator and the Android emulator, no code changes and the result is recorded on the issue, because the issue calls the problem unverified.
- If the code does not reach the field's state, the change is limited to the code field and its shared text field component, and keeps the "Action forms" rule; no change to the sign-in flow, codes, attempt limits, API or the email field, per the non-goals.
- The simulator and emulator may not offer a real SMS suggestion. Where they cannot, the check uses the nearest thing they can do (a pasted code, or a value set by the platform's autofill service), and the record says what each platform proved and what stays unproven on a real device, because the check is only as good as the input it can produce.
- A Playwright `fill()` is not accepted as proof for either criterion, because it fires the same events as typing (A4 has no separate test row; it restricts the tests in rows 1 and 2).

## Test matrix

| AC  | Test                                                                                                                                                                                                                                                                                          | Level  | Where                |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | -------------------- |
| 1   | Open the code step on the iOS Simulator (Safari) and the Android emulator (Chrome), fill the field by autofill or paste, press "Đăng nhập", and check that the code is submitted and the groups page opens. Evidence: screenshots or a recording of each platform in the issue comment or PR. | manual | `apps/web`, Mac mini |
| 2   | Same setup with a wrong code: press "Đăng nhập", and check that the error shows and the field still holds the filled code. Same evidence.                                                                                                                                                     | manual | `apps/web`, Mac mini |

Both are manual because no tool in the repo drives a mobile browser's autofill: Playwright `fill()` cannot reproduce the problem and Maestro covers the native app only. If the check finds a defect, the plan adds a regression test that reproduces the missed event (for example dispatching the value change without a React-visible input event) before the fix.

## Out of scope

- Any change to the sign-in flow, codes, attempt limits or the API.
- Any change to the email step's field.
- A fix, unless the check shows the problem; that is planned then.

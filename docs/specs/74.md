# CI: mobile-e2e runs on what it depends on, frees port 3101, keeps the API log on cancel

Issue: #74 · Runs on: `mac` · Status: waiting for gate 1

## User story

As the repository owner, I want `mobile-e2e` to run whenever what it depends on changes, to leave the Mac mini ready for the next run, and to keep the API log when a run is cancelled, so that a red or cancelled run can be read and the next one doesn't fail on something the last one left behind.

## Acceptance criteria

1. Given a PR that changes only `.github/workflows/mobile-e2e.yml`, `scripts/e2e-lock.sh`, `pnpm-lock.yaml` or `docker-compose.yml`
   When the PR is opened or pushed to
   Then a `mobile-e2e` job runs on the `macos-sim` runner
2. Given a PR that changes none of those files and none of `apps/mobile/**`, `packages/shared/**` or `apps/api/**`
   When the PR is opened or pushed to
   Then no `mobile-e2e` job runs
3. Given a run is cancelled or times out while the API is listening on port 3101
   When the cleanup step runs
   Then, only while it holds the e2e lock, it stops whatever listens on 3101 and logs its PID and command line, and afterwards 3101 is free, so the next run doesn't fail with "Port 3101 is already in use"
4. Given something listens on port 3001, or on any port other than 3101
   When the cleanup step runs
   Then it is left running; and if the e2e lock stays held, the cleanup stops nothing on 3101 either
5. Given a run is cancelled while `e2e:ios` or `e2e:android` is running
   When the job ends
   Then the `mobile-e2e-output` artifact holds `api-ios.log` or `api-android.log` for the run that was stopped
6. Given a run that passes, or one that fails without a cancel
   When the job ends
   Then it uploads the same files as today, and the fork guard (`head.repo.full_name == github.repository`), `permissions: contents: read` and the `pull_request`-only trigger are unchanged

## Assumptions

- The path filter keeps the three existing paths and adds the four from criterion 1, because the issue says the job must also run on those and says nothing about dropping any.
- Only `.github/workflows/mobile-e2e.yml` changes, because the issue's scope is CI only.

## Out of scope

- Making `mobile-e2e` a required check, and runs on pushes to `main`.
- Any change to `docs/specs/26.md`.

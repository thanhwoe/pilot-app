# Web: the sign-in code field can lose an edit made while its action is pending

Issue: #59 · Runs on: `cloud` · Status: waiting for gate 1

## User story

As someone signing in on the web, I want a code I corrected while the "sign in" request is still running to stay in the field when the request ends, so that I don't have to type it again.

## Acceptance criteria

1. Given I am on the code step and I submit a wrong code
   When I type the right code in the field while that request is still pending and the request then fails with the wrong-code error
   Then the field still holds the code I typed and the error shows

2. Given I am on the code step and I submit the right code
   When the request succeeds
   Then I am signed in and sent home, as today

## Assumptions

- The first step is to reproduce the loss by holding the request open, as the #55 test does, because the issue says the cause is likely but not yet reproduced. If it does not reproduce, the PR says so and the test stays as a regression guard.
- Only the code step's field changes; the email step's field, the sign-in flow, codes, attempt limits and the API stay as they are, as the issue's non-goals say.

# Sign-in: send codes by email, then re-check code autofill on a real phone

Issue: #87 · Runs on: `cloud` · Status: waiting for gate 1

## User story

As someone signing in, I want my sign-in code delivered to me by email, so that I can sign in without reading it from the API log, and so that my phone can offer the code it received.

## Acceptance criteria

1. Given the API has an email provider key configured
   When I ask for a code on the web or in the app
   Then an email with that code is sent to the address I gave, from `Góp <onboarding@resend.dev>`

2. Given the API has no email provider key configured
   When I ask for a code
   Then the code is delivered as it is today (written to the API log), and no request goes to the email provider

3. Given the API sends codes by email
   When a code is issued
   Then the code is not written to the API log

4. Given the email provider rejects the send or cannot be reached
   When I ask for a code
   Then the request fails with a generic error that has no provider detail, and the log holds no code

5. Given the web is served by `next dev` and `ALLOWED_DEV_ORIGINS` lists the phone's origin
   When the phone opens the web
   Then the dev server accepts the origin; with the variable empty or unset, `allowedDevOrigins` stays empty and no host name is committed

6. Given a code email reached an iPhone (iOS 17 or later) and I open the code step in Safari
   When I look at the keyboard suggestion for the field
   Then it offers the code, picking it fills the field, and "Đăng nhập" signs me in. If plain `http://` on the LAN offers nothing, the check is repeated once over HTTPS and the record says which was used

## Assumptions

- The sender calls Resend's HTTPS API with `fetch`, with no new dependency, because the call is one request.
- A failed send makes `POST /auth/code` answer with a generic 500 and the existing error handling, because the sender throws and the route has no catch. The issued code stays in the store and expires after 10 minutes as today; the attempt limit on codes still applies.
- The email is plain text in Vietnamese, with the code and its 10-minute lifetime. The code appears as its own line so a phone can find it. Exact wording is chosen in the plan.
- With `onboarding@resend.dev`, Resend delivers only to the address of the key's owner. The phone check signs in with that address.
- The phone check runs by hand by the owner on the Mac and real phones. The evidence goes in `docs/evidence/87/` with the key revoked afterwards. It is not part of CI.
- The key lives only in a git-ignored `.env` and in `apps/api/.env.example` as an empty name; it is never in CI or a GitHub secret.

## Out of scope

- A change to codes, attempt limits or the sign-in flow.
- SMS.
- A sending domain, a real sender address, or a deployed environment.
- Changing how CI or the e2e runs deliver codes (they keep the log sender and `DEV_SIGN_IN_CODES`).
- A fix to the code field, unless the phone check shows a defect; that would be planned then.

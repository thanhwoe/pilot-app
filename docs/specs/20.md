# Web: the create-group form clears the name after a failed create

Issue: #20 · Runs on: `cloud` · Status: waiting for gate 1

## User story

As a signed-in member using the web app, I want the create-group form to keep the name I typed when the create fails, so that I can retry without retyping it, as I can on mobile.

## Acceptance criteria

1. Given I am signed in on the web and the API cannot be reached
   When I submit the create form with a name
   Then I see "Không kết nối được máy chủ. Hãy thử lại.", the field still holds the name I typed, and no group is created
2. Given I am signed in on the web
   When I submit the create form with a name of only spaces
   Then I see "Hãy nhập tên nhóm.", the field still holds exactly what I typed, and no group is created
3. Given I am signed in on the web
   When I create a group successfully
   Then the group shows at the top of my groups with "1 thành viên" and the field is empty

## Assumptions

1. Every failed create keeps the typed name, the connection error and the empty-name error alike. Only a success clears the field. Mobile already behaves this way, so the two apps match.
2. A create that ends in sign-in, because the session is gone, keeps no name. It sends me to the sign-in page, as #19 specifies.
3. The field shows the name as typed, untrimmed. Trimming stays the API's job.
4. Criterion 1 has no automated end-to-end test, as agreed on the issue. It needs a second web server pointed at an unreachable API, as in #14 and #19. Both failures come back through the same branch of the create action, so the criterion 2 test shows that branch keeps the name. Criterion 1 is checked by hand with the API stopped.

## Out of scope

- Any API change
- Any mobile change, because mobile already keeps the name
- New copy: the existing error messages are reused
- An automated end-to-end test for an unreachable API
- Changing what the form does with the name on success beyond what #14 specified

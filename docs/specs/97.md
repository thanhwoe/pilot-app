# Mobile: a group's expenses, and adding one with an equal split

Issue: #97 · Runs on: `mac` · Status: waiting for gate 1

## User story

As a member of a group, I want to see a group's expenses and add one from my phone in a few taps, so that I record it when I pay.

## Acceptance criteria

1. Given my groups list in the app
   When I tap a group
   Then a screen for that group opens, showing the group's name

2. Given a group with expenses
   When its screen is open
   Then the expenses are listed newest first, each with its description, its amount in whole VND with thousands separators and "₫", its date, and who paid: "Bạn đã trả" when I paid, otherwise "<email> đã trả" with the payer's email

3. Given a group with no expenses
   When its screen is open
   Then it shows an empty state instead of a list, and the action to add an expense

4. Given the group screen
   When I open "add expense", enter an amount and a description, and save
   Then the expense is stored as paid by me and split equally between all the group's members, the form closes, and the expense shows at the top of the group's expense list

5. Given the amount field
   When I type or paste into it
   Then only whole VND can be entered (digits only), and it is shown with thousands separators as I type

6. Given an empty description or one of only spaces, an amount of zero, or an amount above 100,000,000 VND
   When I press save
   Then I see the error, nothing is stored, and what I typed stays in the form

7. Given a request that fails, because the API can't be reached or answers with an error
   When I press save
   Then I see the error, what I typed stays in the form, and nothing is stored

8. Given the save button
   When I press it twice before the screen re-renders
   Then one expense is stored

9. [security] Given the API rejects my session (401 `unauthorized`)
   When the group screen loads its group or expenses, or I save an expense
   Then the session ends and sign-in shows, as it does on the groups list, and any other failure keeps the session

10. Given a member of a group
    When they ask the API for that group
    Then the answer is the group (id, name, member count, creation time) with its members, each with their user id and email, in the order they joined

11. [security] Given a user who is not a member of a group, an id no group has, or an id that is not a valid id
    When they ask the API for that group
    Then they get the same 404 `not_found` for all three, with no member's email in the answer; and a call with no session or an ended one gets 401 `unauthorized`

12. Given a signed-in user
    When the session is restored at app start or sign-in completes
    Then the signed-in state holds the user's id as well as their email

13. Given the new texts (the add-expense action, the form labels and errors, the empty state, "Bạn đã trả" and "<email> đã trả")
    When they are shown on mobile
    Then they come from the shared copy, and tests check their exact strings

## Assumptions

1. Tapping a group's row on the groups list opens its screen, and going back returns to the groups list, because the screen opens from the existing list.
2. After a successful save the form closes and the list is reloaded from the API, with no optimistic insert, because that is what the issue's intake assumed and the owner confirmed.
3. The amount field takes at most 9 digits, ignores every other character, and shows groups of three digits separated by "." as I type, because the largest allowed amount has 9 digits and the app is Vietnamese.
4. Rows show an amount as, for example, `90.000 ₫`, with "." between groups of three digits and "₫" after a space, because that is how Vietnamese amounts are written.
5. A row's date is written `dd/MM/yyyy` in the device's time zone, because the issue asks for a date and gives no format.
6. "All the group's members" are the members the group screen last loaded, and the save sends their ids; a member who joined after that is included after the next reload, because the API accepts only current members and a shorter list stays valid.
7. The save button is disabled while the request runs, and what I typed stays after any error, as the create-group form does, because the issue asks that nothing typed is lost.
8. Every call that sends the session token goes through the shared session guard, and a screen never handles a 401 itself, because `CLAUDE.md` requires it.
9. A group screen whose load fails shows the connection error with a "Thử lại" button and keeps the session, as the groups list does, because the issue's error cases imply it and the repo already settles how.
10. A description is trimmed and is 1 to 200 characters, and the form accepts at most 200, because those are the shared limits the owner confirmed.
11. `GET /groups/:id` answers with the existing group fields plus `members`, in their own response schema; the create and join answers stay as they are, and nothing else calls `GET /groups/:id` today, because the owner decided so on the issue.
12. The payer is shown by email because there are no display names yet, and members see each other's email, because the owner decided so on the issue.
13. The evidence is Jest tests plus Maestro flows on the iOS Simulator and on the Android emulator (`Pixel_9_API_35`), with a screenshot of each in the PR; the owner has no Android phone, so the emulator stands in for one, because `CLAUDE.md` says to say so.
14. Descriptions typed in Maestro flows are ASCII, because Maestro can't type other text on Android.

- Choosing another payer or another split (the next issue after this one).
- The receipt photo.
- Balances on mobile.
- Editing and deleting an expense.
- Display names, and any web screen for expenses.
- Offline use, and paging of a long expense list.

# Groups: invite by link and join, on the API and the web

Issue: #94 · Runs on: `cloud` · Status: waiting for gate 1

## User story

As a member of a group, I want to share an invite link so that the people I split costs with can join the group.

## Acceptance criteria

1. Given I am a member of a group
   When I ask for its invite link from my groups list on the web
   Then I get a link that holds a token for that group, and I can copy it

2. Given a signed-in user who is not a member
   When they open a valid invite link
   Then they see the group's name and a "join" button, and pressing it makes them a member and the group appears in their list

3. Given a user who is already a member
   When they open the group's invite link
   Then they go to their groups list, where the group already is, and nothing changes

4. Given someone who is signed out
   When they open an invite link
   Then they are asked to sign in first and come back to the invite afterwards

5. [security] Given an invite link with a token that is wrong, malformed or belongs to no group
   When it is opened or used to join
   Then nothing is joined, and the answer doesn't tell which part was wrong

6. [security] Given a user who is not a member of a group
   When they ask for that group's invite link
   Then they get no link, and the answer doesn't reveal whether the group exists

7. [security] Given a group's invite link
   When a member makes a new one
   Then the old link joins no one (with the same answer as a wrong token, criterion 5), and the new one works

8. [security] Given a group's invite token
   When it is stored
   Then only its hash is kept, so the database never holds a working link; the link is shown only when it is made, and the page says that showing it again means making a new one

## Assumptions

- A group has one link at a time, and it has no expiry: it works until a member replaces it (owner's comment on the issue).
- Any member can make or reset the link, because there are no roles yet.
- The token is `randomBytes(32)` as base64url, hashed like `sessions.tokenHash`, the same way sessions are made and kept (owner's comment).
- Asking for a link when the group has none makes the first one; asking again makes a new one and ends the old one.
- A signed-out visitor who signs in lands back on the same invite, not on the groups list (criterion 4).
- Calls that send the session token go through `guardSession`; a rejected session ends the session as for other group calls.

## Out of scope

- A page for one group: the web has only the groups list today.
- The mobile app and deep links (a separate `mac` issue).
- Removing members, leaving a group, or roles.
- Email invitations.
- Link expiry, and more than one link per group.

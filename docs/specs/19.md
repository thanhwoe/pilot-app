# Groups: an expired session shows the connection error instead of sign-in

Issue: #19 · Runs on: `mac` · Status: waiting for gate 1

## User story

As a member whose session has expired on the API, I want the groups section to send me to sign-in, so that I'm not stuck retrying a request that will always fail.

## Acceptance criteria

### Web

1. [security] Given I am signed in on the web and my session has ended on the API
   When I submit the create-group form with a valid name
   Then I land on the sign-in page, the session cookie is gone from the browser, and no group was created
2. [security] Given my session cookie is still in the browser
   When the home page loads and the API answers 401 `unauthorized` to the groups list, even though it accepted the session for the account line
   Then I land on the sign-in page and the session cookie is gone

### Mobile

3. [security] Given I am signed in on the mobile app and my session has ended on the API
   When I tap "Tạo nhóm" with a valid name
   Then the stored token is deleted, the sign-in screen shows, and no group was created
4. [security] Given the app holds a token
   When the groups list loads and the API answers 401 `unauthorized`
   Then the stored token is deleted and the sign-in screen shows

### What doesn't change

5. Given the API can't be reached, times out or answers with a server error
   When the groups list loads or I create a group, on web or mobile
   Then the groups section shows "Không kết nối được máy chủ. Hãy thử lại." and the session is kept: the web cookie or the mobile token is still there
6. Given I am signed in and my session is valid
   When I submit an empty name, or the API answers 400 `invalid_request` to a create
   Then the form shows "Hãy nhập tên nhóm." and the session is kept

## Assumptions

1. Sign-in shows as it does for any signed-out visit, with no message about the expired session, because that is what already happens when the account check gets a 401 on either app.
2. The app doesn't ask the API to end the session first, because the API has already rejected that token; only this device's copy needs removing.
3. Only a 401 `unauthorized` from the groups calls signs the user out. Every other answer keeps today's behaviour (criteria 5 and 6).

## Out of scope

- Any API change: the group routes already answer 401 `unauthorized` (#14, AC 11).
- A message on the sign-in screen saying the session expired (assumption 1).
- A general 401 handler for API calls other than the groups ones.
- Keeping the group name I typed across sign-in.
- A missing or unreadable token on mobile while the home screen shows: it still shows the connection error, a different failure from the one in this issue.
- A way for Maestro to end a session from outside, such as a dev-only endpoint. If the plan wants a mobile E2E flow for AC 3 and 4, it raises that at gate 2.

# Web: remove the unused name from the create-group failure state

Issue: #54 · Runs on: `cloud` · Status: waiting for gate 1

## User story

As the developer, I want the create-group action to stop sending back a name that nothing reads, so that the form's field value has one owner and the failure state holds only what the screen shows.

## Acceptance criteria

1. Given a create fails (empty name, API unreachable, 404, 429 or 400)
   When `createGroupAction` returns
   Then its state is `{ error }` and has no `name` field

2. Given a create fails
   When the form shows the error
   Then the field still holds what the member typed, as `#20 AC 2` and `#51 AC 1` check today

3. Given I submit a valid name and the create succeeds
   When I typed another name while it was pending
   Then the field still holds what I typed

4. Given I submit a valid name and the create succeeds
   When the field still holds the submitted name
   Then the field is cleared

5. Given a create succeeds
   When `createGroupAction` returns
   Then its state carries the submitted name and has no `error`

## Assumptions

- The scope also covers `apps/web/src/app/create-group-form.tsx`: its effect clears the field only when the field still equals the `name` in the success state. The issue's added criteria need this, though its Scope section names only the action and its test.
- On success the state's `name` is the submitted value as typed, not trimmed, because the field holds it as typed.
- A success state is told apart from the initial `{}` by `name` being present. Two successes with the same name each clear the field, because each returns a new state object.
- Web only: no change to the API, mobile or `packages/shared`.
